2 · Lectura Comprensiva del Modelo

Cómo entender las 10 tablas antes de escribir código

Todas las tablas usan id NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY más códigos o nombres únicos (UNIQUE). Se organizan en tres capas:

1. Tablas Catálogo (Padres)

regiones, tipos, arenas, objetos.

No dependen de nadie (no tienen claves foráneas). Guardan los datos maestros que se reutilizan en todo el sistema.

2. Tablas Dependientes (1:N)

entrenadores, especies, pokemones_capturados, combates.

Tienen columnas terminadas en _id (claves foráneas) que apuntan al id de su tabla padre.

3. Tablas Pivote (N:M)

inventario_entrenador, participaciones_combate.

Conectan dos tablas entre sí mediante dos claves foráneas y agregan datos propios del cruce (ej. cantidad o dano_infligido).

2 · Estructura de Tablas (1/3)

Capa 1: Tablas Catálogo (Sin Claves Foráneas)

CREATE TABLE regiones (
    id                NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    codigo            VARCHAR2(10) NOT NULL UNIQUE,
    nombre            VARCHAR2(40) NOT NULL UNIQUE,
    profesor_regional VARCHAR2(50) NOT NULL,
    generacion        NUMBER(2)    NOT NULL
);

CREATE TABLE tipos (
    id               NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nombre           VARCHAR2(30) NOT NULL UNIQUE,
    categoria_ataque VARCHAR2(20) NOT NULL,
    clima_favorable  VARCHAR2(30) NOT NULL
);
CREATE TABLE arenas (
    id                NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nombre            VARCHAR2(60) NOT NULL UNIQUE,
    ciudad            VARCHAR2(50) NOT NULL,
    superficie        VARCHAR2(20) NOT NULL,
    capacidad_publico NUMBER(6)    NOT NULL
);

CREATE TABLE objetos (
    id            NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nombre        VARCHAR2(50) NOT NULL UNIQUE,
    categoria     VARCHAR2(25) NOT NULL,
    precio_tienda NUMBER(6)    NOT NULL,
    es_consumible CHAR(1)      DEFAULT 'S' NOT NULL
);

Observa el patrón: Aunque todas tienen id numérico automático como PRIMARY KEY, también protegen sus códigos o nombres de negocio con NOT NULL UNIQUE para impedir duplicados.

Capa 3: Tablas Pivote (Muchos a Muchos)

Un entrenador puede tener muchos objetos y un objeto puede estar en la mochila de muchos entrenadores. Lo mismo ocurre entre combates y Pokémon capturados:

-- Conecta entrenadores con objetos:
CREATE TABLE inventario_entrenador (
    id                NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    cantidad          NUMBER(3) DEFAULT 1 NOT NULL,
    fecha_adquisicion DATE      NOT NULL,
    entrenador_id     NUMBER    NOT NULL REFERENCES entrenadores(id),
    objeto_id         NUMBER    NOT NULL REFERENCES objetos(id)
);
-- Conecta combates con pokemones_capturados:

    id                  NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    dano_infligido      NUMBER(5) DEFAULT 0 NOT NULL,
    dano_recibido       NUMBER(5) DEFAULT 0 NOT NULL,
    debilitados_rivales NUMBER(1) DEFAULT 0 NOT NULL,
    gano                CHAR(1)   NOT NULL,
    combate_id          NUMBER    NOT NULL REFERENCES combates(id),
    pokemon_id          NUMBER    NOT NULL REFERENCES pokemones_capturados(id)
);

3 · Cápsula Pedagógica · Etapa 1 de 5 (DDL)

Cómo construir un CREATE TABLE con restricciones

CREATE TABLE nombre_tabla (
    -- 1. Clave primaria autogenerada:
    id        NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    -- 2. Código único obligatorio:
    codigo    VARCHAR2(10) NOT NULL UNIQUE,
    -- 3. Valor por defecto + obligatorio + regla CHECK:
    nivel     NUMBER(3) DEFAULT 15 NOT NULL
              CHECK (nivel BETWEEN 5 AND 100),
    estado    CHAR(1)   DEFAULT 'N' NOT NULL
              CHECK (estado IN ('S', 'N')),
    -- 4. Clave foránea hacia tabla padre:
    region_id NUMBER NOT NULL REFERENCES regiones(id)
);

Regla 1: Orden de `DEFAULT` y `NOT NULL`

En Oracle, cuando una columna tiene valor por defecto y además es obligatoria, siempre se escribe primero DEFAULT valor y después NOT NULL.

Regla 2: Orden de creación de tablas

Primero debes crear la tabla maestra (gimnasios) y después la tabla pivote (retos_gimnasio), porque la hija necesita referenciar a gimnasios(id).

Regla 3: Sin coma en la última línea

Cada definición de columna se separa con coma, pero la última línea antes de cerrar el paréntesis ); no lleva coma.

3 · Cápsula Pedagógica · Etapa 2 de 5 (DML)

Cómo insertar datos con IDENTITY, DEFAULT y TO_DATE

-- Caso A: Insertando todas las columnas (sin incluir 'id')
INSERT INTO gimnasios (
    codigo_gym, nombre, ciudad, nivel_sugerido, region_id, tipo_id
) VALUES (
    'GYM-02', 'Gimnasio Celeste', 'Ciudad Celeste', 25, 1, 2
);

-- Caso B: Omitiendo 'nivel_sugerido' para que actúe su DEFAULT 15
INSERT INTO gimnasios (
    codigo_gym, nombre, ciudad, region_id, tipo_id
) VALUES (
    'GYM-04', 'Gimnasio Pirita', 'Ciudad Pirita', 4, 7
);

-- Caso C: Insertando una fecha con formato estándar ISO
INSERT INTO retos_gimnasio (
    codigo_acta, fecha_reto, entrenador_id, gimnasio_id
) VALUES (
    'ACT-103', TO_DATE('2026-10-06', 'YYYY-MM-DD'), 8, 3
);

1. Nunca incluyas la columna id

Como fue definida con GENERATED ALWAYS AS IDENTITY, Oracle calcula el número automáticamente. Si intentas enviar un valor para id, arrojará el error ORA-32795.

2. Cómo activar un valor DEFAULT

Simplemente no menciones esa columna en la lista de columnas de INSERT INTO (...) ni en VALUES (...). Oracle rellenará el valor por defecto automáticamente.

3. Fechas seguras con TO_DATE

Usa siempre TO_DATE('YYYY-MM-DD', 'YYYY-MM-DD') para no depender del idioma o formato regional del computador donde se ejecute.

3 · Cápsula Pedagógica · Etapas 3 y 4 (DML)

Modificar con UPDATE y eliminar con DELETE

Estructura de UPDATE

-- Actualizar varias columnas:
UPDATE retos_gimnasio
SET gano_medalla = 'S',
    recompensa_pokedolares = 2800
WHERE codigo_acta = 'ACT-103';

-- Incremento porcentual (+20%):
UPDATE retos_gimnasio
SET recompensa_pokedolares = recompensa_pokedolares * 1.20
WHERE gano_medalla = 'S' AND intentos <= 2;

Regla vital: Si olvidas la cláusula WHERE en un UPDATE, modificarás todas las filas de la tabla.

Estructura de DELETE e Integridad

-- Para borrar un registro padre que tiene hijos:
-- Paso 1: Borrar primero el registro hijo (dependiente)
DELETE FROM retos_gimnasio
WHERE codigo_acta = 'ACT-106';

-- Paso 2: Borrar después el registro padre (maestro)
DELETE FROM gimnasios
WHERE codigo_gym = 'GYM-06';

¿Por qué ese orden? Si intentas borrar un gimnasio que aún tiene retos asociados, Oracle bloquea la acción con ORA-02292 (child record found) para evitar registros huérfanos.

3 · Cápsula Pedagógica · Etapa 5 de 5 (DDL)

Las 4 operaciones de ALTER TABLE en Oracle

Cuando una tabla ya existe y tiene datos cargados, usamos ALTER TABLE para evolucionar su estructura sin perder los registros:

-- 1. ADD: Agregar una nueva columna
ALTER TABLE gimnasios
ADD lider_titular VARCHAR2(40) DEFAULT 'Por asignar' NOT NULL;

-- 2. MODIFY: Cambiar el tamaño o tipo de una columna
ALTER TABLE gimnasios
MODIFY lider_titular VARCHAR2(80);

-- 3. ADD CONSTRAINT: Agregar una regla con nombre
ALTER TABLE retos_gimnasio
ADD CONSTRAINT chk_reto_modalidad
CHECK (modalidad IN ('Individual', 'Doble', 'Triple'));

-- 4. DROP COLUMN: Eliminar una columna obsoleta
ALTER TABLE gimnasios
DROP COLUMN nota_inspector;

¿Por qué ADD con NOT NULL exige DEFAULT?

Si la tabla ya tiene filas guardadas y agregas una columna obligatoria (NOT NULL), Oracle necesita saber qué valor ponerles a las filas existentes. Con DEFAULT 'Por asignar' las rellena al instante.

Buenas prácticas con ADD CONSTRAINT

Darle un nombre descriptivo a la restricción (ej. chk_reto_modalidad) permite identificar de inmediato qué regla falló si un usuario intenta ingresar un dato inválido.

4 · Fundamentos de Consultas · Bloques 1 y 2

Proyección, Cálculos Matemáticos y Alias (AS)

SELECT nombre AS especie_pokemon,
       ataque_base,
       defensa_base,
       -- Suma simple:
       ataque_base + defensa_base AS poder_combate,
       -- Promedio de 3 columnas con paréntesis y redondeo:
       ROUND((ataque_base + defensa_base + velocidad_base) / 3, 1)
           AS media_stats
FROM especies;

Cálculos fila por fila

Las operaciones +, -, * y / en el SELECT calculan una columna virtual para el reporte sin modificar los datos guardados en la tabla.

Cuidado con la prioridad matemática

La división / y multiplicación * se ejecutan antes que la suma +. Para promediar varias columnas, encierra siempre la suma entre paréntesis antes de dividir.

Redondeo con ROUND(valor, decimales)

ROUND(x, 2) deja 2 decimales; ROUND(x, 0) redondea al número entero más cercano.

4 · Fundamentos de Consultas · Bloque 3

Filtrado de filas con WHERE y operadores lógicos

-- 1. Paréntesis obligatorios al mezclar OR con AND:
SELECT fase_torneo, asistencia_publico
FROM combates
WHERE (fase_torneo = 'Semifinal' OR fase_torneo = 'Gran Final')
  AND asistencia_publico > 25000;

-- 2. Listas (IN), Rangos (BETWEEN) y Patrones (LIKE):
SELECT num_pokedex, nombre, ataque_base
FROM especies
WHERE es_legendario = 'N'
  AND ataque_base BETWEEN 80 AND 135
  AND (nombre LIKE 'C%' OR nombre LIKE 'T%');

Trampa 1: Mezclar OR y AND sin paréntesis

En SQL, AND tiene mayor precedencia que OR. Si necesitas que se cumpla (A o B) y además C, debes escribir (A OR B) AND C.

Trampa 2: Usar un alias del SELECT en el WHERE

Oracle ejecuta el WHERE antes de leer los alias del SELECT. Si filtras por una suma, escribe la operación completa en el WHERE, no el alias.

Comodines de LIKE

'C%' empieza con C · '%Ball%' contiene "Ball" en cualquier posición.

4 · Fundamentos de Consultas · Bloques 4 y 5

Ordenar (ORDER BY) y Agrupar (GROUP BY)

Regla de Oro de GROUP BY (Evita ORA-00979)

SELECT region_id,
       rango,
       COUNT(*) AS total_entrenadores,
       SUM(pokedolares) AS riqueza_total
FROM entrenadores
GROUP BY region_id, rango
ORDER BY region_id ASC, riqueza_total DESC;

Toda columna en el SELECT que no esté dentro de COUNT, SUM, AVG, MIN o MAX debe repetirse obligatoriamente en el GROUP BY.

¿Cuándo lleva GROUP BY y cuándo no?

• Si piden un resumen de toda la tabla en 1 sola fila (ej. "el total de especies"), usa solo COUNT(*) sin GROUP BY.
• Si dicen "por cada..." (por cada región, por cada rango, por cada categoría), necesitas GROUP BY.

ORDER BY sí acepta Alias

Como ORDER BY es el último paso que ejecuta Oracle, puedes ordenar directamente por el alias de una columna calculada o agregada (ej. ORDER BY riqueza_total DESC).

4 · Fundamentos de Consultas · Bloques 6 y 7

Cómo cruzar tablas con INNER JOIN sin confundirse

-- 1. Cruzar 2 tablas (Hija -> Padre):
SELECT e.alias_entrenador, r.nombre AS region
FROM entrenadores e
INNER JOIN regiones r ON e.region_id = r.id;

-- 2. Cruzar tabla pivote + agrupar (JOIN + GROUP BY):
SELECT e.alias_entrenador,
       COUNT(*) AS tipos_items,
       SUM(inv.cantidad * o.precio_tienda) AS valor_mochila
FROM inventario_entrenador inv
INNER JOIN entrenadores e ON inv.entrenador_id = e.id
INNER JOIN objetos o      ON inv.objeto_id = o.id
GROUP BY e.alias_entrenador
ORDER BY valor_mochila DESC;

1. Siempre usa alias de tabla cortos

Varias tablas tienen columnas llamadas id o nombre. Definir FROM especies esp INNER JOIN tipos t y escribir esp.nombre y t.nombre evita el error ORA-00918 (column ambiguously defined).

2. ¿Qué va en la condición ON?

En el ON siempre se iguala la clave foránea de la tabla dependiente con la clave primaria (id) de la tabla maestra: ON hija.padre_id = padre.id.

4 · Mapa Mental para la Evaluación

Orden en que escribes vs. Orden en que ejecuta Oracle

Respetar la secuencia sintáctica al escribir y comprender el orden interno de ejecución resuelve el 90% de los errores en SQL:

1. Orden obligatorio al ESCRIBIR tu consulta:

1. SELECT
→
2. FROM
→
3. INNER JOIN ... ON
→
4. WHERE
→
5. GROUP BY
→
6. ORDER BY

2. Orden real en que ORACLE EJECUTA tu consulta internamente:

1° FROM / JOIN
→
2° WHERE
→
3° GROUP BY
→
4° SELECT (crea los Alias)
→
5° ORDER BY (usa los Alias)

Esto explica por qué un alias creado en el SELECT (paso 4°) todavía no existe cuando se evalúa el WHERE (paso 2°), pero sí existe cuando se ordena en el ORDER BY (paso 5°).
