1 · Estructura de Tablas (1/3)

Tablas Catálogo

CREATE TABLE regiones (
    id                 NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    codigo             VARCHAR2(10) NOT NULL UNIQUE,
    nombre             VARCHAR2(50) NOT NULL UNIQUE,
    servidor_principal VARCHAR2(40) NOT NULL
);

CREATE TABLE patrocinadores (
    id          NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nombre      VARCHAR2(60) NOT NULL UNIQUE,
    rubro       VARCHAR2(40) NOT NULL,
    pais_origen VARCHAR2(40) NOT NULL
);
CREATE TABLE agentes (
    id          NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nombre      VARCHAR2(40) NOT NULL UNIQUE,
    rol         VARCHAR2(20) NOT NULL,
    origen_lore VARCHAR2(40) NOT NULL
);

CREATE TABLE mapas (
    id           NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nombre       VARCHAR2(40) NOT NULL UNIQUE,
    sitios_bomba NUMBER(1)    NOT NULL,
    ambientacion VARCHAR2(50) NOT NULL
);

1 · Estructura de Tablas (2/3)

Tablas con Relación 1:N

Cada fila apunta a su tabla padre mediante una clave foránea (region_id, equipo_id, mapa_id):

CREATE TABLE equipos (
    id                NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nombre            VARCHAR2(60) NOT NULL UNIQUE,
    tag               VARCHAR2(6)  NOT NULL UNIQUE,
    presupuesto_anual NUMBER(10)   NOT NULL,
    anio_fundacion    NUMBER(4)    NOT NULL,
    region_id         NUMBER       NOT NULL REFERENCES regiones(id)
);

CREATE TABLE jugadores (
    id             NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nickname       VARCHAR2(40) NOT NULL UNIQUE,
    nombre_real    VARCHAR2(80) NOT NULL,
    pais_natal     VARCHAR2(40) NOT NULL,
    edad           NUMBER(2)    NOT NULL,
    sueldo_mensual NUMBER(8)    NOT NULL,
    equipo_id      NUMBER       NOT NULL REFERENCES equipos(id)
);

1 · Estructura de Tablas (3/3)

Tablas Pivote (Muchos a Muchos)

Resuelven relaciones N:M almacenando las claves foráneas de las tablas que conectan más los datos propios del cruce:

-- Conecta equipos con patrocinadores:
CREATE TABLE patrocinios (
    id              NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    monto_anual     NUMBER(9)    NOT NULL,
    tipo_contrato   VARCHAR2(20) NOT NULL,
    equipo_id       NUMBER       NOT NULL REFERENCES equipos(id),
    patrocinador_id NUMBER       NOT NULL REFERENCES patrocinadores(id)
);
-- Conecta jugadores, partidas y agentes:
CREATE TABLE participaciones (
    id              NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    kills           NUMBER(3) NOT NULL,
    deaths          NUMBER(3) NOT NULL,
    assists         NUMBER(3) NOT NULL,
    puntaje_combate NUMBER(4) NOT NULL,
    gano            CHAR(1)   NOT NULL,
    jugador_id      NUMBER    NOT NULL REFERENCES jugadores(id),
    partida_id      NUMBER    NOT NULL REFERENCES partidas(id),
    agente_id       NUMBER    NOT NULL REFERENCES agentes(id)
);

2 · Fundamentos de SELECT

Estructura mínima de una consulta

SELECT columnas
FROM tabla;

SELECT indica qué columnas queremos ver; FROM indica desde qué tabla se extraen.

2 · Fundamentos de SELECT

Consultar todas las columnas (*)

SELECT *
FROM productos;

El asterisco * devuelve todas las columnas de la tabla en su orden original.

2 · Fundamentos de SELECT

Seleccionar columnas específicas

SELECT nombre, precio
FROM productos;

Las columnas se separan con coma. Después de la última columna antes de FROM no va coma.

2 · Fundamentos de SELECT

Operaciones matemáticas en el SELECT

SELECT nombre,
       precio * stock
FROM productos;

Calcula un nuevo valor fila por fila usando +, -, * o / sin alterar los datos guardados.

2 · Fundamentos de SELECT

Renombrar columnas con Alias (AS)

SELECT nombre AS producto,
       precio * stock AS valor_inventario
FROM productos;

AS asigna un nombre legible al encabezado de la columna en el resultado.

3 · Filtrado con WHERE

Filtrar filas con WHERE

SELECT nombre, precio
FROM productos
WHERE precio > 50000;

WHERE se ubica después de FROM y deja pasar únicamente las filas que cumplen la condición.

3 · Filtrado con WHERE

Filtrar por texto exacto (=)

SELECT nombre, precio
FROM productos
WHERE categoria = 'Audio';

En SQL los textos van entre comillas simples 'Audio' y distinguen entre mayúsculas y minúsculas.

3 · Filtrado con WHERE

Condiciones simultáneas con AND

SELECT nombre, categoria, precio
FROM productos
WHERE categoria = 'Audio'
  AND precio >= 70000;

Con AND, la fila debe cumplir todas las condiciones al mismo tiempo.

3 · Filtrado con WHERE

Condiciones alternativas con OR

SELECT nombre, categoria, precio
FROM productos
WHERE categoria = 'Audio'
   OR categoria = 'Video';

Con OR, basta con que la fila cumpla al menos una de las condiciones.

3 · Filtrado con WHERE

Rangos con BETWEEN

SELECT nombre, precio
FROM productos
WHERE precio BETWEEN 30000 AND 80000;

Equivale a precio >= 30000 AND precio <= 80000 (incluye ambos extremos).

3 · Filtrado con WHERE

Listas de valores con IN

SELECT nombre, categoria
FROM productos
WHERE categoria IN ('Audio', 'Video', 'Redes');

Comprueba si el valor coincide con cualquiera de los elementos dentro del paréntesis.

3 · Filtrado con WHERE

Búsqueda de texto parcial con LIKE

SELECT nombre
FROM productos
WHERE nombre LIKE '%USB%';

'Pro%'

Empieza con "Pro"

'%USB'

Termina con "USB"

'%USB%'

3 · Filtrado con WHERE

Detectar valores vacíos con IS NULL

SELECT nombre, descuento
FROM productos
WHERE descuento IS NULL;

NULL representa la ausencia de dato. Nunca se usa = NULL; siempre IS NULL o IS NOT NULL.

4 · Ordenamiento con ORDER BY

Ordenar el resultado con ORDER BY

SELECT nombre, precio
FROM productos
ORDER BY precio;

ORDER BY siempre se escribe en la última línea de la consulta.

4 · Ordenamiento con ORDER BY

Direcciones de ordenamiento: ASC y DESC

ASC (Ascendente — por defecto)

Números: menor a mayor (1 → 100)
Texto: alfabético (A → Z)
Fechas: más antigua a más reciente

DESC (Descendente)

Números: mayor a menor (100 → 1)
Texto: alfabético inverso (Z → A)
Fechas: más reciente a más antigua

Operan sobre un conjunto de filas y devuelven un único valor resumido:

5 · Funciones de Agregación y GROUP BY

Agregación sin GROUP BY

SELECT COUNT(*) AS total_productos,
       SUM(stock) AS unidades_totales,
       AVG(precio) AS precio_promedio
FROM productos;
total_productosunidades_totalesprecio_promedio
58886000

Sin GROUP BY, todas las filas de la tabla se resumen en una sola fila.

5 · Funciones de Agregación y GROUP BY

¿Por qué necesitamos GROUP BY?

Cuando no queremos un único total general, sino calcular un resumen por cada grupo distinto dentro de una columna.

Sin GROUP BY

"¿Cuál es el precio promedio de toda la tienda?"
→ Devuelve 1 fila.

Con GROUP BY categoria

"¿Cuál es el precio promedio por cada categoría?"
→ Devuelve 1 fila por cada categoría.

5 · Funciones de Agregación y GROUP BY

Cómo opera GROUP BY paso a paso

1. Agrupa

Reúne todas las filas que tienen el mismo valor en la columna indicada (ej. Audio, Periféricos, Video).

2. Calcula

Aplica la función (COUNT, SUM, AVG, MIN, MAX) al interior de cada grupo por separado.

3. Entrega

Genera una única fila de salida por cada grupo.

5 · GROUP BY · Ejemplo 1

Contar filas por grupo (COUNT)

¿Cuántos productos existen en cada categoría?

SELECT categoria,
       COUNT(*) AS cantidad_productos
FROM productos
GROUP BY categoria;

5 · GROUP BY · Ejemplo 2

Sumar valores por grupo (SUM)

¿Cuántas unidades de stock acumulamos en cada categoría?

SELECT categoria,
       SUM(stock) AS stock_total
FROM productos
GROUP BY categoria;
categoriastock_total
Periféricos55
Audio25
Video8

COUNT(*) cuenta cuántas filas hay en el grupo; SUM(stock) suma los valores numéricos de la columna stock.

5 · GROUP BY · Ejemplo 3

Calcular el promedio por grupo (AVG)

¿Cuál es el precio promedio en cada categoría?

SELECT categoria,
       ROUND(AVG(precio), 0) AS precio_promedio
FROM productos
GROUP BY categoria;

5 · Regla Sintáctica de GROUP BY

La regla fundamental de GROUP BY

Toda columna presente en el SELECT que no esté dentro de una función de agregación debe aparecer en el GROUP BY.

Incorrecto (ORA-00979)

SELECT categoria, nombre, COUNT(*)
FROM productos
GROUP BY categoria;
-- 'nombre' no está agrupada ni agregada

Correcto

SELECT categoria, COUNT(*)
FROM productos
GROUP BY categoria;

5 · GROUP BY · Ejemplo 5

Agrupar por más de una columna

Forma subgrupos combinando ambas columnas (por ejemplo, cada combinación de categoría y estado):

SELECT categoria,
       estado,
       COUNT(*) AS cantidad
FROM productos
GROUP BY categoria, estado;

6 · Consultas Multitabla (JOIN)

¿Para qué sirve JOIN?

Cuando los datos que necesitamos mostrar están repartidos en dos o más tablas relacionadas entre sí.

Tabla tabla_a

Contiene la clave foránea b_id.

Tabla tabla_b

Contiene la clave primaria id y el nombre o detalle que buscamos.

6 · Consultas Multitabla (JOIN)

Estructura de un JOIN básico

SELECT tabla_a.columna,
       tabla_b.columna
FROM tabla_a
JOIN tabla_b ON tabla_a.b_id = tabla_b.id;

La cláusula ON iguala la clave foránea de una tabla con la clave primaria de la otra.

6 · Consultas Multitabla (JOIN)

Uso de alias de tabla en JOIN

SELECT p.nombre AS producto,
       p.precio,
       c.nombre AS categoria
FROM productos p
JOIN categorias c ON p.categoria_id = c.id;

Definir un alias corto en FROM productos p y JOIN categorias c abrevia la consulta y evita ambigüedades cuando ambas tablas tienen columnas llamadas id o nombre.

6 · Consultas Multitabla (JOIN)

Cruzar una tabla pivote (Doble JOIN)

Partimos desde la tabla intermedia y conectamos hacia cada tabla maestra:

SELECT a.nombre,
       b.nombre,
       piv.monto
FROM pivote piv
JOIN tabla_a a ON piv.a_id = a.id
JOIN tabla_b b ON piv.b_id = b.id;

6 · Consultas Multitabla (JOIN)

Agrupar después de hacer JOIN

SELECT c.nombre AS categoria,
       COUNT(*) AS total_productos
FROM productos p
JOIN categorias c ON p.categoria_id = c.id
GROUP BY c.nombre
ORDER BY total_productos DESC;

Al unir las tablas primero, podemos agrupar directamente por el nombre de la categoría en vez de su código numérico.

7 · Aplicación del Método · Caso 1

"Mostrar nickname, sueldo mensual y nombre del equipo de los jugadores que ganan más de 20.000, ordenados de mayor a menor sueldo"

1. Análisis

Mostrar nickname, sueldo_mensual y nombre del equipo. Filtrar sueldos mayores a 20000.

2. Estrategia

Los datos están en jugadores y equipos. Unir por equipo_id = id.

3. Herramientas

JOIN ... ON, WHERE > 20000 y ORDER BY DESC.

SELECT j.nickname,
       j.sueldo_mensual,
       e.nombre AS equipo
FROM jugadores j
JOIN equipos e ON j.equipo_id = e.id
WHERE j.sueldo_mensual > 20000
ORDER BY j.sueldo_mensual DESC;

7 · Aplicación del Método · Caso 2

"Mostrar el nombre de cada agente y el total de kills logradas con él en el torneo, de mayor a menor"

1. Análisis

Mostrar un resumen de kills totales agrupado por el nombre de cada agente.

2. Estrategia

Cruzar participaciones con agentes mediante agente_id = id y agrupar.

3. Herramientas

JOIN, SUM(kills), GROUP BY a.nombre y ORDER BY DESC.

SELECT a.nombre AS agente,
       SUM(p.kills) AS total_kills
FROM participaciones p
JOIN agentes a ON p.agente_id = a.id
GROUP BY a.nombre
ORDER BY total_kills DESC;
