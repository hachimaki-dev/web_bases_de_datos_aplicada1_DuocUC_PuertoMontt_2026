Etapa 1 · Arquitectura del Lenguaje Concepto Distinguir estructura (DDL) vs datos (DML)

¿Cómo se organiza el lenguaje SQL?

SQL (Structured Query Language) no es un bloque único: se divide en sublenguajes especializados según si estamos diseñando los cimientos de la base de datos o trabajando con las filas que viven dentro de ella.

1. DDL — Data Definition Language

Lenguaje de Definición de Datos

Construye, modifica o destruye la estructura (el esqueleto) de las tablas y sus reglas de integridad. No manipula filas individuales.

  • CREATE TABLE: Crea una nueva tabla y sus restricciones.
  • ALTER TABLE: Modifica columnas o agrega reglas a una tabla existente.
  • DROP TABLE: Elimina la tabla completa (estructura y datos).
2. DML — Data Manipulation Language

Lenguaje de Manipulación de Datos

Opera directamente sobre las filas (registros) almacenadas dentro de las tablas que ya fueron creadas con DDL.

  • INSERT INTO: Agrega nuevas filas de datos a una tabla.
  • UPDATE: Modifica valores de filas que ya existen.
  • DELETE FROM: Borra filas específicas sin destruir la tabla.
  • SELECT: Consulta, filtra y recupera información de las tablas.
Analogía de Ingeniería
El DDL equivale a construir el edificio de un banco, instalar las bóvedas y programar las cerraduras de seguridad. El DML equivale a los clientes que entran a depositar, actualizar su saldo, retirar dinero o consultar su cartola.
Etapa 1 · Tipos de Datos Oracle SQL Tipos nativos para columnas

Tipos de Datos Fundamentales en Oracle

Al definir una tabla, cada columna exige un tipo de dato estricto que determina qué valores acepta y cuánto espacio reserva:

Tipo en Oracle Qué almacena Ejemplo de Declaración Uso típico en modelos de negocio
VARCHAR2(n) Texto de longitud variable (hasta n caracteres). Solo ocupa el espacio real del texto ingresado. nombre VARCHAR2(80) Nombres, correos, direcciones, títulos, estados variables.
CHAR(n) Texto de longitud fija exacta. Si ingresas menos letras, rellena con espacios a la derecha. codigo_pais CHAR(2) Códigos ISO fijos ('CL', 'AR'), siglas de largo exacto.
NUMBER(p) Número entero de hasta p dígitos de precisión. stock NUMBER(5) IDs, cantidades en inventario, años (NUMBER(4)), puntajes.
NUMBER(p, s) Número decimal con p dígitos en total, de los cuales s son decimales luego de la coma. precio_usd NUMBER(8, 2) Montos en dólares, porcentajes, pesos o medidas con decimales.
DATE Fecha y hora (siglo, año, mes, día, hora, minuto, segundo). fecha_ingreso DATE Fechas de nacimiento, fechas de contratación, fechas de venta.
¿Cómo se declaran estos tipos en PostgreSQL, MySQL o SQL Server?

En Oracle el estándar industrial para texto es VARCHAR2(n) y para números es NUMBER(p, s).

En PostgreSQL, MySQL y SQL Server se utiliza VARCHAR(n) para texto, INT o INTEGER para enteros, y NUMERIC(p, s) o DECIMAL(p, s) para decimales.

Etapa 2 · DDL Estructural Sintaxis Construcción de tablas con restricciones en línea

Anatomía de CREATE TABLE (Restricciones en Línea)

La sentencia CREATE TABLE transforma una entidad en una tabla física real. En esta primera etapa escribiremos todas las restricciones directamente en la misma línea de cada columna:

Oracle SQL · DDLCREATE TABLE nombre_tabla (
    columna_1   TIPO_DATO   PRIMARY KEY,
    columna_2   TIPO_DATO   NOT NULL UNIQUE,
    columna_3   TIPO_DATO   DEFAULT valor NOT NULL CHECK (condicion_logica),
    columna_4   TIPO_DATO   NOT NULL REFERENCES tabla_padre(columna_pk)
);
REGLA 1

Nombres en Singular y snake_case

Usamos empleado o orden_compra (sin espacios, sin tildes ni letra ñ). Todo en la misma línea de la columna: nombre, tipo y sus reglas.

REGLA 2

Comas Separadoras

Cada definición de columna se separa con una coma , al final de su línea, excepto la última columna antes de cerrar el paréntesis );.

REGLA 3

Orden de Creación

Siempre se crean primero las tablas Padre (Maestras) que no dependen de nadie, y luego las tablas Hija que usan REFERENCES.

Etapa 2 · Integridad de Datos Constraints Las 6 reglas guardianas en la línea de la columna

Las 6 Restricciones (Constraints) en Línea

¿Por qué no basta con validar los datos en el formulario web? Porque la base de datos es la última línea de defensa. Cada restricción se declara en la misma línea de la columna para impedir que entren datos inválidos:

1. PRIMARY KEY

Clave Primaria

Identifica de forma única a cada fila: id NUMBER(4) PRIMARY KEY. Equivale a NOT NULL + UNIQUE automáticamente.

2. REFERENCES (FK)

Clave Foránea en Línea

Conecta con la tabla padre directamente en la línea: id_depto NUMBER(4) NOT NULL REFERENCES departamento(id_depto).

3. NOT NULL

Obligatoriedad

Prohíbe dejar la celda vacía (NULL): nombre VARCHAR2(80) NOT NULL. Equivale al asterisco * del modelo conceptual.

4. UNIQUE

Unicidad Alternativa

Impide que dos filas repitan el mismo valor en esa columna: email VARCHAR2(100) NOT NULL UNIQUE.

5. CHECK (...)

Regla de Dominio

Evalúa una condición lógica en la misma línea: sueldo NUMBER(8) NOT NULL CHECK (sueldo > 0).

6. DEFAULT

Valor por Defecto

Asigna un valor automático si el INSERT omite esa columna. Se escribe antes de NOT NULL: stock NUMBER(5) DEFAULT 0 NOT NULL.

Etapa 2 · Foco en CHECK Reglas de Negocio Blindando cada columna con CHECK en línea

Dominando la Restricción CHECK en la Misma Línea

Un CHECK se escribe al final de la definición de la columna y evalúa una condición lógica por cada fila que intenta entrar o actualizarse. Si la condición es falsa, Oracle rechaza el registro de inmediato:

Patrón 1: Valores Positivos y Rangos (BETWEEN)

-- Impide precios negativos o cero en la misma línea:
precio NUMBER(8, 2) NOT NULL CHECK (precio > 0),

-- Exige que la nota esté entre 1.0 y 7.0 inclusive:
nota   NUMBER(2, 1) NOT NULL CHECK (nota BETWEEN 1.0 AND 7.0),

Patrón 2: Lista Cerrada de Valores (IN)

-- Solo acepta exactamente uno de estos 3 textos:
tipo_jornada VARCHAR2(15) NOT NULL CHECK (tipo_jornada IN ('COMPLETA', 'PARCIAL', 'REMOTA')),

Patrón 3: Combinando Condiciones con DEFAULT

-- Valor por defecto + obligatorio + validación de rango:
descuento NUMBER(3) DEFAULT 0 NOT NULL CHECK (descuento BETWEEN 0 AND 75),

-- Estado con valor inicial por defecto y lista válida:
estado    VARCHAR2(10) DEFAULT 'ACTIVO' NOT NULL CHECK (estado IN ('ACTIVO', 'INACTIVO')),

Patrón 4: Largo Mínimo de Texto (LENGTH)

-- El código SKU debe tener al menos 6 caracteres:
codigo_sku VARCHAR2(10) NOT NULL UNIQUE CHECK (LENGTH(codigo_sku) >= 6)
⚠️ Ojo con las mayúsculas dentro de las comillas simples: Si defines CHECK (estado IN ('ACTIVO', 'INACTIVO')) e intentas insertar 'activo' en minúsculas, ¡Oracle lo rechazará! Los textos entre comillas simples ' ' son sensibles a mayúsculas y minúsculas.
Etapa 2 · DDL en Acción Ejemplo Genérico Tablas Padre e Hija 100% en línea

Ejemplo Integral DDL: DEPARTAMENTO y EMPLEADO

Observa qué limpio y directo queda el código cuando todas las restricciones (PRIMARY KEY, UNIQUE, DEFAULT, CHECK y REFERENCES) se declaran dentro de la línea de cada columna:

Paso 1: Crear Tabla Padre (Maestra) 
CREATE TABLE departamento (
    id_depto      NUMBER(4)     PRIMARY KEY,
    nombre_depto  VARCHAR2(60)  NOT NULL UNIQUE,
    presupuesto   NUMBER(12, 2) DEFAULT 1000000 NOT NULL CHECK (presupuesto >= 0)
);
Paso 2: Crear Tabla Hija (con FK y CHECKs en línea) 
CREATE TABLE empleado (
    id_empleado   NUMBER(6)    PRIMARY KEY,
    rut           VARCHAR2(12) NOT NULL UNIQUE,
    nombre        VARCHAR2(80) NOT NULL,
    sueldo_base   NUMBER(10)   NOT NULL CHECK (sueldo_base >= 500000),
    modalidad     VARCHAR2(15) DEFAULT 'PRESENCIAL' NOT NULL CHECK (modalidad IN ('PRESENCIAL', 'HIBRIDO', 'REMOTO')),
    id_depto      NUMBER(4)    NOT NULL REFERENCES departamento(id_depto)
);
Etapa 2 · Evolución del Esquema DDL Modificar y eliminar tablas

Modificando y Destruyendo Estructuras: ALTER y DROP

En proyectos reales los requerimientos cambian: necesitamos agregar una columna nueva con sus propias reglas en línea, ampliar una columna o eliminar una tabla experimental.

1. ALTER TABLE — Modificar sin perder datos

-- A) Agregar columna con DEFAULT y NOT NULL en línea:
ALTER TABLE empleado
    ADD fecha_contrato DATE DEFAULT SYSDATE NOT NULL;

-- B) Agregar columna con su CHECK en la misma línea:
ALTER TABLE empleado
    ADD bono_mensual NUMBER(8) DEFAULT 0 NOT NULL CHECK (bono_mensual >= 0);

-- C) Modificar el largo o tipo de una columna:
ALTER TABLE empleado
    MODIFY nombre VARCHAR2(120);

-- D) Eliminar una columna que ya no se usa:
ALTER TABLE empleado
    DROP COLUMN bono_mensual;

2. DROP TABLE — Destrucción total

-- Elimina la estructura y TODOS sus datos:
DROP TABLE empleado;
DROP TABLE departamento;

-- Si deseas borrar una tabla padre rompiendo sus FKs hijas:
DROP TABLE departamento CASCADE CONSTRAINTS;
🛑 Regla del Orden Inverso al Borrar:
Así como creamos Padre → Hija, al eliminar con DROP TABLE debemos borrar primero la tabla Hija (empleado) y luego la tabla Padre (departamento).

Etapa 3 · DML: Poblamiento INSERT Agregando registros a las tablas

Poblando Tablas con INSERT INTO

Una vez creadas las tablas con DDL, usamos INSERT INTO para insertar filas respetando los tipos de datos y todas las restricciones activas.

Oracle SQL · DML-- 1. Inserción explícita completa (¡Buena práctica profesional!):
INSERT INTO departamento (id_depto, nombre_depto, presupuesto)
VALUES (10, 'Informatica', 25000000);

-- 2. Aprovechando el valor DEFAULT (omitimos la columna 'presupuesto'):
INSERT INTO departamento (id_depto, nombre_depto)
VALUES (20, 'Recursos Humanos'); -- Oracle le asigna 1000000 automáticamente

-- 3. Insertando en tabla hija con fechas (TO_DATE) y valores NULL:
INSERT INTO empleado (id_empleado, rut, nombre, sueldo_base, modalidad, id_depto)
VALUES (101, '21.345.678-9', 'Ana Gomez', 950000, 'REMOTO', 10);
TEXTOS

Comillas Simples ' '

En SQL los textos van SIEMPRE entre comillas simples: 'Ana Gomez'. Nunca uses comillas dobles " " para valores.

FECHAS ORACLE

Función TO_DATE y SYSDATE

Para fechas exactas usa TO_DATE('2026-03-15', 'YYYY-MM-DD'). Para la fecha actual del servidor usa SYSDATE.

AUSENCIA DE DATO

Palabra clave NULL

Si una columna es opcional (no tiene NOT NULL), puedes pasar NULL sin comillas: VALUES (..., NULL).

Etapa 3 · DML: Actualización UPDATE Modificando registros existentes

Actualizando Datos con UPDATE

La sentencia UPDATE modifica una o más columnas de las filas que cumplan la condición indicada en la cláusula WHERE.

Oracle SQL · DML-- 1. Actualizar un registro específico usando su Clave Primaria (PK):
UPDATE empleado
SET sueldo_base = 1100000,
    modalidad   = 'HIBRIDO'
WHERE id_empleado = 101;

-- 2. Actualización masiva con cálculo matemático (+10% de reajuste al depto 10):
UPDATE empleado
SET sueldo_base = sueldo_base * 1.10
WHERE id_depto = 10;
🚨 LA REGLA DE ORO DEL UPDATE: ¡Nunca olvides el WHERE!
Si ejecutas UPDATE empleado SET sueldo_base = 500000; sin cláusula WHERE, el motor actualizará ABSOLUTAMENTE TODAS LAS FILAS DE LA TABLA (desde el practicante hasta el gerente general). Además, todo UPDATE también pasa por la revisión de los CHECK y FOREIGN KEY.
Etapa 3 · DML: Eliminación DELETE Borrado de filas e integridad referencial

Eliminando Filas con DELETE FROM

DELETE elimina filas completas de una tabla según el filtro WHERE, manteniendo intacta la estructura de la tabla y sus restricciones.

-- 1. Borrar un registro puntual por su PK:
DELETE FROM empleado
WHERE id_empleado = 101;

-- 2. Borrar con condición compuesta (AND):
DELETE FROM empleado
WHERE modalidad = 'REMOTO'
  AND sueldo_base < 600000;

-- 3. ¡PELIGRO! Sin WHERE vacía toda la tabla:
DELETE FROM empleado;
🔒 Protección de Clave Foránea al Borrar

Si intentas borrar el departamento 10 (DELETE FROM departamento WHERE id_depto = 10;) mientras aún tiene empleados trabajando en él, Oracle bloqueará la orden con el error ORA-02292: child record found. Primero debes reasignar o borrar a los hijos.

💾 COMMIT y ROLLBACK

En Oracle, tus cambios de INSERT, UPDATE y DELETE se confirman permanentemente con COMMIT; o se deshacen en caso de accidente con ROLLBACK;.

Etapa 4 · Consultas SQL SELECT Proyección, cálculos y alias

Consultando Datos: SELECT, Cálculos y Alias

La sentencia SELECT permite leer y transformar los datos en información útil sin alterar lo que está guardado en el disco.

Oracle SQL · SELECT-- 1. Consultar todas las columnas de una tabla:
SELECT * FROM empleado;

-- 2. Seleccionar columnas específicas, calcular expresiones y renombrar con AS:
SELECT nombre                     AS nombre_trabajador,
       sueldo_base                AS sueldo_mensual,
       sueldo_base * 12           AS sueldo_anual,
       ROUND(sueldo_base * 0.20)  AS bono_estimado
FROM empleado;
PROYECCIÓN

Elegir Columnas

En lugar de traer todo con *, indica solo las columnas que necesita tu reporte separadas por coma.

ARITMÉTICA

Cálculos al Vuelo

Puedes sumar +, restar -, multiplicar *, dividir / y redondear con ROUND(valor, decimales).

ALIAS (AS)

Títulos Legibles

AS nuevo_nombre cambia el encabezado de la columna en el resultado visual sin cambiar la tabla real.

Etapa 4 · Filtrado de Filas WHERE Operadores lógicos y especiales

Filtrando Filas con WHERE y sus Operadores

La cláusula WHERE filtra qué filas aparecen en el resultado. Más allá de =, >, <, >=, <= y <> (distinto), SQL ofrece 4 operadores clave:

-- 1. Rango inclusivo con BETWEEN:
SELECT nombre, sueldo_base
FROM empleado
WHERE sueldo_base BETWEEN 700000 AND 1200000;

-- 2. Lista de valores con IN:
SELECT nombre, modalidad
FROM empleado
WHERE modalidad IN ('REMOTO', 'HIBRIDO');
-- 3. Búsqueda de patrones de texto con LIKE:
-- '%' representa cualquier secuencia de caracteres
SELECT nombre FROM empleado
WHERE nombre LIKE 'Ana%'; -- Empieza con 'Ana'

-- 4. Evaluar valores nulos (¡NUNCA uses = NULL!):
SELECT nombre FROM empleado
WHERE id_jefe IS NULL;     -- No tiene jefe
-- O bien: WHERE id_jefe IS NOT NULL;
💡 Combinando condiciones: Usa AND cuando ambas condiciones deben cumplirse al mismo tiempo, y OR cuando basta con que se cumpla al menos una (usa paréntesis si mezclas AND y OR).
Etapa 4 · Nivel Intermedio-Avanzado Reportería ORDER BY, GROUP BY e INNER JOIN

Ordenamiento, Agrupación y Cruce de Tablas (JOIN)

Para resolver los últimos ejercicios del desafío de hoy, combinaremos estas tres herramientas de análisis:

1. Ordenar (ORDER BY) y Resumir (GROUP BY)

-- Funciones de agregación:
-- COUNT(*), SUM(col), AVG(col), MIN(col), MAX(col)
SELECT modalidad,
       COUNT(*)               AS total_empleados,
       ROUND(AVG(sueldo_base)) AS sueldo_promedio
FROM empleado
GROUP BY modalidad
ORDER BY total_empleados DESC; -- ASC o DESC

2. Unir Tablas Normalizadas (INNER JOIN)

-- Conecta la FK de la tabla hija con la PK de la padre:
SELECT e.nombre        AS empleado,
       e.sueldo_base,
       d.nombre_depto  AS departamento
FROM empleado e
INNER JOIN departamento d
    ON e.id_depto = d.id_depto
ORDER BY d.nombre_depto ASC;
Orden Sagrado de Escritura en un SELECT
SELECT (columnas) → FROM (tabla base) → INNER JOIN ... ON (cruces) → WHERE (filtros de fila) → GROUP BY (agrupación) → ORDER BY (orden final).
